## 问题

DPO 是什么？它相比 PPO 式的 RLHF 简化了什么？各有什么取舍？

## 核心答案

- **DPO（Direct Preference Optimization）**：直接用**偏好数据对（同一个问题的好回答/坏回答）**做监督式的偏好优化，跳过"训练奖励模型 + RL 在线采样"两个重环节。
- **简化了什么**：
  1. 不用单独训练和维护 RM；
  2. 不用在线生成 + 打分 + 更新的 RL 训练循环（PPO 管道复杂、超参敏感、算力开销大）；
  - 训练形态退化成"类似 SFT 的离线训练"，稳定性和实现难度大幅下降。
- **直觉理解**：数学上可以推导出"奖励与策略的对数比"存在解析关系——DPO 等效于隐式地包含了一个奖励模型，把 RL 目标转写成了直接在偏好对上的损失函数。
- **取舍**：
  - DPO：简单稳定便宜 → 开源社区与资源有限团队的主流选择；
  - RLHF（PPO 类）：在线探索、奖励信号可动态更新，上限更高，但工程与调参门槛高；
  - 共同前提：**偏好数据的质量决定天花板**，垃圾偏好对训谁都救不回来。
- 领域迭代快（还有 IPO/KTO 等变体），面试讲到"DPO 简化了 RM+RL、偏好对直接监督"这一层即可，注明以最新文献为准。

## 深度解析

- DPO 的弱点：离线训练依赖偏好数据的分布覆盖，对训练分布外的行为泛化较弱；且对偏好对的"好/坏差距"敏感（噪声对会直接损伤模型）；
- 实务选择参考：常规对话风格对齐、开源模型对齐 → DPO；需要复杂约束、在线反馈、安全红线严苛的大厂场景 → RLHF 系仍是主力；
- 面试定位：说清"简化了什么、为什么可行、各自适用"，展示对对齐阶段工程复杂度的理解。
