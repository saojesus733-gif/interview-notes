## 问题

Base 模型和 Instruct/Chat 模型有什么区别？做应用时用哪个？微调时从哪个开始？

## 核心答案

- **Base（基座）模型**：只经过预训练，本质是"文本补全机"——给它一段话，它做的是**最可能的续写**。你问它问题，它可能不回答，反而"模仿你继续提问"或续写出更多问题。
- **Instruct/Chat 模型**：Base + SFT（+ 偏好对齐）的产物——理解指令、按对话轮次交互、知道何时拒答、遵循格式。
- **工程含义**：
  1. 做应用（问答/Agent/RAG）**一律用 Chat 模型**；误用 Base 模型的典型症状：回答变成续写、答完又生成新问题、不遵守系统指令；
  2. API 选型时认准模型名的后缀（-chat / -instruct / base），同一个底座两种形态能力天差地别；
3. **微调起点**：
  - 领域适配（风格/格式/话术）→ 在 Chat 模型上继续 SFT，成本低见效快；
  - 从 Base 全流程自训（SFT+对齐都自己做）→ 只有数据充足、有训练团队时才考虑；
  - 补全类任务（续写/代码补全）反而应该用 Base 模型——它的"补全天性"正是所需。

## 深度解析

- 两者差异的本质是**训练目标不同**：Base 的目标是"预测下一词"（分布上贴近训练语料的延续），Chat 的目标是"完成人类指令"——同一段前文，两者的最优续写完全不同；
- 面试追问预判："那 few-shot 在 Chat 模型上还有用吗？"→ 有用但作用变化：从"教格式"变成"统一口径与风格"，格式更多靠模板与系统指令保证；
- 实验意识：同一 prompt 在 Base/Chat 上的输出差异巨大，做过一次对比实验这题就稳了。
