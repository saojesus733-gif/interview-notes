## 问题

你的 RAG 系统接了法规类知识库，法规频繁修订。用户问新规，系统却引用旧条文回答。怎么系统性解决？

## 核心答案

**根因分析**：向量库里新旧版本并存，语义相近的旧条文照样被召回，且模型无从判断哪条现行有效——这是**数据治理问题**，不是检索算法问题。

**解决方案（四层）**：

1. **元数据管理**：每个 chunk 强制带 `生效日期 / 失效日期 / 文档版本 / 条文状态`；入库时"新版本入库 + 旧版本标记 superseded"，而不是简单覆盖；
2. **检索过滤**：查询时预过滤 `status = 现行`，只允许现行条目进入召回池；时间敏感问题把"当前日期"注入 query/Prompt；
3. **冲突消解**：同一条文多版本同时命中时，按版本号/生效日期去重取最新，并在 Prompt 中告知模型"以 X 年修订版为准"；
4. **更新管道**：源文档变更 → 触发增量重建索引（只重嵌变更章节）→ 灰度生效；配监控：过期条目残留量、新旧冲突命中率。

**兜底设计**：对"价格/政策/时效"类强敏感回答，输出必须附带"依据：XX 文件（X 年 X 月生效）"，并设置"政策类回答强制提示以官方最新为准"。

## 深度解析

- 加分点：指出"删除旧文档"是常见错误做法——审计需要历史版本追溯，正确姿势是版本化存储 + 状态标记，检索层只看现行视图；
- 知识库运营要建立"更新 SLA"：法规发布到入库生效的时延上限，超时告警——RAG 的时效性是运营问题 + 工程问题共同保证；
- 该题可迁移到价格库、库存、组织架构等一切"频繁变动的私有知识"场景，答题时点一句通用性。
