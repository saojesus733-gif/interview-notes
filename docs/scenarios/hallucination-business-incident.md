## 问题

客服 Agent 在用户投诉时"幻觉"出一条不存在的赔付政策并承诺了用户，引发客诉升级。作为技术负责人，你怎么止血？怎么防止再次发生？

## 核心答案

**止血（当天）**：

1. 下线相关能力：涉及赔付/承诺类的回答切到"转人工"固定话术（功能级降级，不是全量下线）；
2. 排查影响面：从日志捞同期所有带"承诺类"表述的会话，交给人工团队主动跟进；
3. 对外口径：客服团队话术同步，避免二次发酵。

**防复发（分层加固）**：

1. **知识边界**：赔付政策等高风险条目走**结构化配置**（金额、条件由规则引擎输出），不让模型自由发挥；政策未覆盖的场景必须落到固定话术；
2. **Prompt 约束**：明确"只能引用知识库编号条目作答；未命中条目时说'需要人工确认'"，并把可承诺的范围枚举给模型；
3. **执行层拦截**：输出走敏感承诺检测（金额/赔偿/保证类词表 + 分类器），命中即改写为人工话术；
4. **高危动作人审**：任何资金相关操作必须 HITL（本来就不该让 Agent 直接承诺）；
5. **评估补位**：把本次事故 case 加进评估集，新增"承诺合规性"维度跑回归。

**复盘（体系化）**：归因到具体薄弱层（知识缺失？检索未命中？生成越界？拦截缺失？），每一层补对应防线，并形成"高危清单"机制——新增高风险意图必须先配置边界再放开。

## 深度解析

- 本质教训：**幻觉无法根除，所以高危语义的输出不能依赖模型自觉**，必须在确定性代码层兜底（规则引擎、词表拦截、人审）；
- 加分点：区分"生成幻觉"与"知识真空"——如果政策文档里根本没写，这是知识运营问题，补文档 + 设计拒答路径比改 Prompt 更治本；
- 面试时主动提"影响面回捞"和"评估集补 case"，体现事故处置的完整闭环意识。
