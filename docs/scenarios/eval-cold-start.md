## 问题

你的 RAG 应用要上线，老板问"效果怎么评估？"——你手上没有任何标注数据。评估集从哪来？

## 核心答案

**四条来源，按启动速度排序**：

1. **LLM 反向生成 + 人工快审**：从知识库文档中让 LLM 生成"问题 + 参考答案"对，人工快速审核修正——最快起量，但偏差是"只覆盖文档有的内容、问法偏理想化"；
2. **业务方访谈**：和客服/运营聊"用户最常问的 30 个问题"——覆盖真实意图，产出快且天然带业务权重；
3. **真实流量采样**：上线后第一周埋点收集全部 query，人工挑典型问题补入——这是最珍贵的来源，尽早开始收集；
4. **竞品/公开基准**：同领域公开数据集可参考题型结构，但口径必须换成自己的业务。

**落地节奏**：上线前用①+②凑够 50~100 条（覆盖主要意图 + 边界 case + 超纲拒答题）；上线后每周用③替换/补充，逐步把合成数据换成真实标注。

**设计要点**：分层覆盖（事实型/推理型/超纲型）、带金标准答案、固定版本号——评估集是资产，要像代码一样管理。

## 深度解析

- 必须主动讲合成数据的坑：LLM 生成的 question 措辞干净、答案都在文档里——真实用户是模糊的、多问的、问文档里没有的；所以合成集只能"起步"，不能"定稿"；
- 早期没有标注时，用**代理指标**过渡：检索命中率（人工快速判"检到的对不对"比写答案快 10 倍）、用户点赞率；
- 与"场景：从零到一"呼应：评估集建设是冷启动主线的一部分，上线第一天就要开始攒。
