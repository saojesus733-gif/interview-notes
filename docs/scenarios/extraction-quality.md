## 问题

用 LLM 从发票 PDF 抽取字段（金额、税号、日期等）供财务系统入库，当前合格率 85%。业务要求到 98%，你的提升路径是什么？

## 核心答案

**第一步：归因分析（不看错误分布就优化 = 瞎调）**——对 15% 的失败样本逐条标注错误类型：

- **输入质量类**（常见大头）：PDF 版面解析错（表格错位、数字被切断）→ 输入就错了，模型无能为力；
- **格式类**：JSON 不合法、字段类型错 → 约束解码问题；
- **抽取类**：金额大小写不一致、含税/不含税搞混 → 指令与业务规则问题；
- **长尾类**：手写发票、模糊盖章 → 模型能力边界。

**第二步：对症提升**：

1. 输入侧：升级版面解析（表格结构还原、OCR 校对），发票这种强模板文档甚至可以用"识别框选 + 坐标定位"减少自由抽取；
2. 格式侧：JSON Schema 约束解码 + Pydantic 校验 + 解析失败带错重试；
3. 抽取侧：few-shot 给足标准示例；业务规则显式写入（"金额以大写为准"）；字段校验规则（税号位数、金额 = 单价×数量）做**代码级后校验**，不一致走重试/人工；
4. 架构侧：一次抽整页 → 拆成"逐区域抽取"，降低单次难度；
5. 长尾：低于置信度阈值的自动路由人工，**保证入库质量 100%，把"自动化率"与"准确率"分开汇报**。

**第三步：评估闭环**：标注 200+ 张分层样本做金标准集，每次改动跑字段级准确率回归，达标（98%）才放量。

## 深度解析

- 98% 的现实含义：靠模型单点做不到，靠"模型 + 规则校验 + 低置信转人工"的**系统**做到——财务场景甚至要求"自动抽取的必须有校验链背书"，这是答出高级感的关键；
- 加分点：交叉验证手段——金额大写小写互验、税号校验位算法、合计与分项求和比对，规则能验证的绝不靠模型自信；
- 该框架（归因 → 分层优化 → 评估放量）适用于一切结构化抽取场景。
