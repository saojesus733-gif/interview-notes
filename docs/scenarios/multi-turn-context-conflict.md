## 问题

用户在订机票的对话中先是说"帮我订下周去北京的机票"，几轮后改口"算了改订上海的"，Agent 却仍然下单了北京的机票。多轮对话的意图漂移怎么解决？

## 核心答案

**根因**：Agent 把"任务参数"和"对话流"混在自然语言历史里，没有把"当前任务状态"显式管理——新意图被旧上下文稀释，或干脆没触发重新确认。

**解决方案**：

1. **任务状态结构化**：把订票任务建模为槽位状态机 `{出发地, 目的地, 日期, 舱位, 状态}`，存在会话状态里而不是散在对话文本中；
2. **意图变更检测**：每轮先做"变更识别"（可用规则 + 轻量模型）：新输入与当前槽位冲突（目的地变了）→ 触发更新流程，而不是继续执行；
3. **变更即确认**：关键槽位（目的地、日期、金额）变更后，**必须回显新参数并获得用户确认**才允许执行写操作——"北京 → 上海，机票日期不变，确认吗？"；
4. **执行前一致性校验**：真正下单前，工具执行层再校验一次参数与会话确认记录一致（代码级兜底，不信模型）；
5. **上下文构建优化**：构建 Memory 时把"当前槽位状态"作为结构化事实放在显眼位置，避免被长对话淹没。

## 深度解析

- 本质是两层防御：模型层（变更检测 + 确认话术）负责体验，代码层（执行前校验确认记录）负责兜底——与"永不信任模型输出参数"同一原则；
- 加分点：指出这类事故在评估中容易被漏掉，测试集要专门覆盖"中途改需求""撤销""参数回填"等对话路径（对话状态跟踪，DST）；
- 该模式可泛化到所有"多轮 + 写操作"场景：改订单、改地址、改预约，核心都是"槽位状态机 + 变更确认 + 执行前校验"。
