## 问题

线上一个研究型 Agent 偶发执行几十轮不终止，单次任务 token 花费是正常值的 50 倍。作为负责人，你怎么治理？

## 核心答案

**止血（先控住线上）**：

1. **硬预算上限**：单任务最大轮数（如 25 步）、最大 token、最大费用、墙钟超时，四道闸任一触发即终止并输出"已完成的部分结论"；
2. **熔断告警**：单任务花费超阈值（如 P99 的 3 倍）实时告警并自动终止。

**排查（分析失控 case）**：

1. 读终止任务的执行轨迹，归类失败模式：工具反复报错 → 模型反复换姿势重试；两个动作来回横跳 → 规划震荡；观察内容互相矛盾 → 模型在"自我说服"；
2. 看上下文：任务执行到后期，历史里是否堆满失败的工具输出，把目标稀释了。

**根治（按失败模式改）**：

1. **震荡检测器**：识别重复动作序列（同工具同参数、或 A→B→A 环），命中后注入纠偏提示（"你已重复尝试 X，请换路径或求助人工"）；
2. **计划固化 + 显式重规划**：按 Plan-and-Execute 结构化推进，重规划设次数上限；
3. **工具结果瘦身**：失败的错误信息摘要化，不无限堆进上下文；
4. **进度锚点**：每步输出结构化进度（完成/未决/结论），让模型始终"看得见目标"。

## 深度解析

- 根因多半是 Context Engineering 问题而非模型问题：长循环中目标与进度的占比被工具噪音淹没，模型失去全局感；
- 加分点：给出分层预算设计——正常任务预算从历史分布取 P95 而不是拍脑袋；预算临界时注入"总结收尾"指令而不是硬杀，用户体验更好；
- 治理效果要用数据验证：治理后统计单任务成本分布与任务完成率，确认没有"为了省钱杀掉长任务"。
