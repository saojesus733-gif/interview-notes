## 问题

新业务线要上智能问答：没有知识库、没有标注数据、没有历史日志。给你 90 天，怎么从零到一？

## 核心答案

**核心思想：先小闭环上线收集真实数据，数据飞轮比完美架构重要。**

**阶段一（第 1~2 周）：最小可用**

1. 盘数据源：散落的产品文档、工单记录、FAQ、网页，能捞多少捞多少；
2. 最小 RAG：清洗 → 切分 → Embedding 入库 → 基础检索问答，不追求效果，先跑通；
3. 同步埋点：记录全部 query、命中情况、用户反馈（赞/踩/转人工）——**数据采集从第一天开始**。

**阶段二（第 3~6 周）：建立评估与迭代**

1. 从内测流量抽 50~100 个真实问题，人工标注金标准答案——第一版评估集；
2. 用评估集驱动优化：切分参数、检索策略（混合检索+Rerank）、Prompt 约束；
3. 没有标注的问题用"知识库反向生成 QA + 人工快审"补充覆盖。

**阶段三（第 7~12 周）：闭环与增强**

1. 高频问题 FAQ 化 + 语义缓存（降成本提速度）；
2. 接入业务工具（查订单/工单状态），从"纯问答"升级为"可执行"；
3. 拒答与转人工闭环：答不了不硬答，人工答案回流进知识库；
4. 看板：解决率、转人工率、负反馈率——用数据决定是否扩大开放。

## 深度解析

- 冷启动的两难：没数据没法评估，没上线没数据——破局点是**小流量内测 + 反馈回流**，先让数据飞轮转起来；
- 加分点：明确"不要在第一天上 Agent"——先 RAG 把知识问答做稳，工具调用等增强能力在数据支撑下逐步加（与 Workflow/Agent 边界同理）；
- 90 天结束时你拥有的不只是系统，而是：真实 query 分布、评估集、反馈通道——这三样才是持续迭代的地基。
