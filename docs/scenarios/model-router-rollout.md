## 问题

你的应用全量用旗舰大模型，月账单很高。计划把其中"简单问答"流量切到便宜 20 倍的小模型，怎么安全地推进？

## 核心答案

**第一步：流量分域（先搞清楚要切什么）**：

1. 按意图/场景把流量分类：FAQ、闲聊、格式化任务适合小模型；复杂推理、多约束、工具编排密集的留在大模型；
2. 用历史日志估各域流量占比与 token 消耗，算出理论省钱上限——优先切"占比大、难度低"的域。

**第二步：离线验证**：

1. 从目标域抽真实问题做测试集（含边界 case）；
2. 大小模型同题对比：正确率、拒答恰当性、格式通过率、延迟；
3. 设准入标准（如"小模型在该域正确率 ≥ 大模型的 98%"），不达标不上线。

**第三步：线上灰度**：

1. **分流架构**：网关按百分比把目标域流量导给小模型（影子模式先行：小模型结果只记日志不返回，与大模型答案离线对比）；
2. 盯质量代理指标：该域的负反馈率、重新提问率、转人工率与大模型基线比，无显著恶化再放量（5% → 25% → 50% → 100%）；
3. 大小模型答案不一致的样本自动落库，人工抽检校准分界线。

**第四步：持续运营**：分域成本与质量看板；用户问题分布变化时重跑验证（小模型域可能需要回切）。

## 深度解析

- 该场景的本质是"分域清晰度"决定成败：分不干净的域宁可不切，混域切换是质量事故的主要来源；
- 加分点：影子模式（shadow traffic）先行可以在零风险下拿到线上分布的真实对比，比纯离线评估可信得多；
- 配套一句边界策略：小模型低置信时升级到大模型（router 带置信度），让回切成为正常路径而不是事故响应。
