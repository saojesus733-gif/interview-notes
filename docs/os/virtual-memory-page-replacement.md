## 问题

什么是虚拟内存？当物理内存不够用时，操作系统如何决定把哪个页面换出去？说说常见的页面置换算法。

## 核心答案

- 虚拟内存：每个进程拥有独立的虚拟地址空间，由 MMU 通过页表映射到物理内存；
  作用是**进程隔离、按需加载、扩大寻址范围**。
- 物理内存不足时，把不活跃页换出到磁盘（Swap），进程因此可以「用得比物理内存多」。
- **缺页中断**：访问的页不在内存时触发异常，内核从磁盘调入页面、更新页表，然后重新执行该指令。
- **FIFO**：淘汰最早进入内存的页，实现简单；可能出现 Belady 异常（页框变多缺页反而变多）。
- **LRU**：淘汰最久未访问的页，效果最接近最优；但严格实现需要维护时间戳或链表，开销大。
- **Clock（时钟/二次机会）**：LRU 的近似实现，环形链表 + 访问位；
  指针扫到访问位为 1 就清零放过，为 0 就淘汰，兼顾效果与开销。

## 深度解析

- 地址翻译流程：虚拟地址拆出页号 → 查 TLB（命中直接得物理页号）→ 未命中查多级页表 → 拼上页内偏移得到物理地址。
- **抖动（Thrashing）**：进程分到的页框太少，频繁缺页，CPU 时间都耗在换页上，系统吞吐骤降；
  解法是降低多道程序度或按工作集模型分配内存。
- Linux 的实际做法：active/inactive 两条 LRU 链表 + 反向映射，是对 LRU 的工程化近似，而非严格时间戳。
- 追问延伸：给定访问序列手算 FIFO/LRU/Clock 的缺页次数是经典笔试题，要会画表格。
- 常见误区：缺页中断不等于「换页」——首次访问也缺页（ demand paging ），此时只是调入而非置换。
