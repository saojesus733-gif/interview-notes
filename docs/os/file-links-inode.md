## 问题

Linux 下删除文件到底删了什么？硬链接和软链接有什么区别？为什么目录不能创建硬链接？

## 核心答案

- **inode**：文件的元数据节点，存储权限、属主、大小、时间戳、数据块指针和**链接计数**；
  文件名不存放在 inode 里，而是存在目录项（dentry）中，目录是「名字 → inode 号」的映射表。
- **硬链接**：`ln source target`，多个文件名指向同一个 inode，链接计数加 1；
  删掉任意一个名字，只要计数不为 0，数据就一直存在。
- **软链接（符号链接）**：`ln -s`，是一个独立的新文件（有自己的 inode），内容是目标的路径；
  目标被删后软链接变成悬空链接，无法访问。
- **删除文件的本质**：链接计数减 1；当计数为 0 **且**没有进程打开该文件时，才真正释放 inode 与数据块。
- 目录不能硬链接：会形成引用环，破坏目录树的层次结构和 `..` 语义的一致性，文件系统遍历可能死循环；
  `.` 和 `..` 是内核特意维护的特例。

## 深度解析

- 硬链接的限制：不能跨文件系统（inode 号只在同一文件系统内唯一）、不能对目录；
  软链接用路径引用，跨文件系统、指向目录都可以。
- 排查技巧：`ls -i` 看 inode 号、`stat file` 看链接数、`df -i` 看 inode 使用量；
  大量小文件会打光 inode，出现「磁盘没满却写不进文件」的现象。
- 经典问题「文件删了但磁盘没释放」：仍有进程持有文件句柄，
  用 `lsof | grep deleted` 找到进程，重启或清空对应文件描述符即可。
- 常见误区：软链接文件本身的大小是目标路径字符串的长度，不是目标文件的大小。
