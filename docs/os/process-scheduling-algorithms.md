## 问题

操作系统面对一堆待运行进程，如何决定下一个运行谁？说说常见调度算法的思路、优缺点和适用场景。

## 核心答案

- **FCFS（先来先服务）**：按到达顺序执行，简单公平；
  但短任务排在长任务后面会长时间等待（护航效应），平均等待时间长。
- **SJF（短作业优先）**：平均等待时间最短；但需要预知运行时长，且长作业可能长期得不到调度（饥饿）。
- **优先级调度**：按优先级执行，实时性好；低优先级进程可能饥饿，需引入**老化（aging）**逐步提升等待久的优先级。
- **时间片轮转（RR）**：每个进程轮流运行一个时间片，响应快、适合交互；
  时间片太长退化为 FCFS，太短则切换开销占比过高。
- **多级反馈队列（MLFQ）**：多个优先级队列，新进程进最高队列，用完时间片就降级，低队列时间片更长；
  无需预知时长，兼顾响应与吞吐，是经典通用调度思想。
- 场景选择：实时系统用优先级调度（RMS/EDF）；交互式系统用 RR 或 MLFQ；批处理系统偏 FCFS/SJF。

## 深度解析

- 抢占与非抢占的区别：SJF 有抢占版本——最短剩余时间优先（SRTF），
  新到达的作业剩余时间更短时可以打断当前进程。
- Linux 实际使用 CFS（完全公平调度器）：按虚拟运行时间（vruntime）在红黑树中挑选最「亏欠」的进程，
  属于公平分享思想，并非教科书式的 MLFQ。
- 时间片长度的权衡是高频追问：通常在「切换开销 < 1%」的前提下尽量保证几十毫秒级的交互响应。
- 常见误区：认为优先级调度一定公平——不加老化机制时低优先级进程会无限期饥饿。
