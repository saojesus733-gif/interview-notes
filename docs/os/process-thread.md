## 问题

进程和线程有什么区别？为什么要有线程？

## 核心答案

- **进程**是资源分配的基本单位，拥有独立的虚拟地址空间、文件描述符表等；
- **线程**是 CPU 调度的基本单位，同进程内的线程共享地址空间和资源，仅私有栈、寄存器上下文和少量线程局部数据。

区别要点：

1. 资源开销：进程创建/切换开销大（要切换页表、刷新 TLB），线程轻量；
2. 隔离性：进程间互不影响，一个线程崩溃可能拖垮整个进程；
3. 通信方式：进程需要 IPC（管道、消息队列、共享内存、Socket），线程直接读写共享变量（需同步）。

为什么要有线程：并发执行时，线程既能共享数据减少开销，又能被独立调度，更适合交互式与并行计算场景。

## 深度解析

- 上下文切换成本：进程切换需保存/恢复页表基址（CR3），导致 TLB 失效；线程切换只需保存寄存器与栈。
- 用户态线程（协程）由用户调度，避免陷入内核，切换成本更低，如 Go goroutine、Java 虚拟线程（Loom）。
- 僵尸进程与孤儿进程：前者需 wait() 回收，后者被 init/systemd 收养。
