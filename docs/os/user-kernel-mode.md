## 问题

操作系统为什么要区分用户态和内核态？什么情况下会发生态切换？一次切换的成本有多大？

## 核心答案

- **为什么分态**：内核态拥有全部硬件权限，若应用代码能直接操作内存和硬件，一个 bug 就能拖垮整个系统；
  分态实现权限隔离，保护内核数据结构与硬件资源。
- **触发时机一：系统调用**（主动）：read/write/fork/brk 等，用户程序请求内核提供服务。
- **触发时机二：中断**（被动）：时钟中断、网卡数据到达、键盘输入等外部硬件事件。
- **触发时机三：异常**（被动）：缺页异常、除零错误、非法指令等，由当前正在执行的指令触发。
- **切换过程**：执行 trap 指令陷入内核 → 保存用户态寄存器现场到内核栈 → 提升特权级执行内核逻辑 → 恢复现场返回用户态。
- **成本**：纳秒到微秒级，包括现场保存恢复、TLB 与 CPU 缓存局部性破坏；高频系统调用会成为性能瓶颈。

## 深度解析

- 特权级由 CPU 硬件保证：x86 分 ring0/ring3，现代 Linux 用 syscall/sysret 指令快速切换，老的 int 0x80 已被淘汰。
- 区分「模式切换」与「进程切换」：系统调用只是同一进程内的特权级切换；
  进程切换还要换页表基址、刷新 TLB，代价大一个数量级。
- 优化方向：减少系统调用次数（writev 合并写、epoll 批量等待）、vDSO 让 gettimeofday 等调用不陷入内核、io_uring 异步批量化 IO。
- 常见误区：把「上下文切换」一律理解成进程切换，寄存器级的模式切换并不等于进程调度切换。
- 追问延伸：可用 strace、perf 统计系统调用次数与耗时，高频小 IO 系统的调优第一步就是砍系统调用。
