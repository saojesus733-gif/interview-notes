## 问题

RAG 系统怎么选 Embedding 模型？需要考虑哪些维度？

## 核心答案

**选型维度**：

1. **效果**：看公开基准（如 MTEB / C-MTEB，注意榜单时效）+ **自己的业务数据实测**——拿真实 query 与文档做召回对比，榜一模型不一定适合你的领域；
2. **语言**：中文场景选中文强的模型；多语言场景看跨语言对齐能力；
3. **维度与成本**：维度越高表达力越强，但存储与检索成本越高（向量库存储 ≈ 维度 × 4 字节 × 条数）；部分模型支持 Matryoshka 截断降维；
4. **最大输入长度**：必须 ≥ chunk 长度，否则文本被截断丢信息；
5. **部署方式**：API 调用（省心、数据出域）vs 私有化（合规、批量成本低）；
6. **生态配套**：是否需要配套 Rerank 模型、推理框架支持。

**工程铁律**：**同一库内查询向量与文档向量必须来自同一模型（含版本）**。换模型 = 全量重新 Embedding 重建索引，embedding 是有版本的资产。

## 深度解析

- Embedding 模型学习的是「语义空间映射」，领域术语密集的场景（医疗/法律）通用模型表现下降，可用领域语料继续对比训练（contrastive fine-tuning）；
- 归一化与相似度度量要配套：归一化后的向量用内积/余弦等价，选库时确认度量方式与模型匹配；
- 评估指标用召回命中率 / MRR / nDCG（在标注 query 上），而不是只看模型自报指标。
