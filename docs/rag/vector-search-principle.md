## 问题

向量检索是怎么工作的？为什么需要 ANN 索引？HNSW 的原理是什么？

## 核心答案

**基本流程**：文本 → Embedding 模型 → 高维向量 → 存入向量库；查询时把 query 同样向量化，按相似度（余弦/内积/L2）找最近的 K 条。

**为什么需要 ANN**：暴力精确检索是 O(N×d)——千万级向量在线逐个比对不可行。**ANN（近似最近邻）**用「牺牲一点召回精度换百倍千倍速度」，是工程上的必然选择。

**主流索引**：

- **HNSW（分层可导航小世界图）**：把向量组织成多层图，顶层稀疏（长边快速跳跃）、底层稠密（精准连接）；查询从顶层贪心下降到目标邻域。特点是高召回、低延迟，支持增量插入；代价是内存占用大、构建慢；
- **IVF（倒排文件）**：先聚类分桶，查询只搜最近的几个桶；
- **PQ（乘积量化）**：向量压缩编码，降内存，精度略损；常与 IVF 组合（IVF-PQ）。

**精度-速度-内存三角**：ef_search / nprobe 等查询参数调「多搜一点更准但更慢」，按 SLA 调优。

## 深度解析

- 过滤与检索的执行顺序很关键：带元数据过滤（租户/权限/时间）时，预过滤可缩小候选集，但过滤太狠会让 ANN 图断边、召回骤降——成熟引擎都有专门处理策略；
- 评估 ANN 看两个数：**召回率（recall@K vs 暴力检索）**和 P99 延迟，上线前必须在自己的数据规模上压测；
- 数据量不大（如百万以内）时，精确检索（flat 索引）+ 简单过滤可能就是最优解，别过度设计。
