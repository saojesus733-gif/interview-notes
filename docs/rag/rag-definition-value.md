## 问题

什么是 RAG？它解决了大模型的哪些根本问题？

## 核心答案

**定义**：RAG（Retrieval-Augmented Generation）= 检索增强生成。回答前先从外部知识库**检索**相关内容，把检索结果作为依据放进 Prompt，再让 LLM 生成回答——「先查资料，再开口」。

**解决三大根本问题**（对应 LLM 的三大知识缺陷）：

1. **知识截止**：模型知识冻结在训练时刻，RAG 的知识库实时可更新；
2. **私有数据缺失**：企业文档、内部数据从未进过训练集，RAG 让「文档进库即可被问答」；
3. **幻觉**：模型没有依据时倾向编造，RAG 强制「依据检索内容作答」，可溯源、可核验，显著压低幻觉。

**一句话本质**：把「知识」从模型参数中解耦到外部可管理的存储，模型专注理解与表达，知识运营（增删改查）回归数据库思维。

**基本流程**：文档切分 → Embedding → 入向量库（离线）；查询向量化 → 召回 Top-K →（重排）→ 拼 Prompt → 生成（在线）。

## 深度解析

- RAG 不是「可选增强」，而是企业知识类应用（客服、文档问答、合规检索）的**默认架构**，因为它把知识维护从「重训模型」降为「运营文档」。
- RAG 的效果上限由检索质量决定：答错多数情况是「没检到」而非「没答好」，优化优先级在检索侧。
- 与长上下文的关系：窗口再大也有成本与注意力稀释，检索依然是把「对的资料」放进窗口的手段。
