## 问题

文档里大量信息在图表、扫描件、图片里，纯文本 RAG 检索不到。多模态 RAG 怎么解决？

## 核心答案

**核心矛盾**：传统链路先把文档转纯文本再检索，图表中的信息在"转文本"环节就丢了。

**三种主流方案**：

1. **文本化方案（Caption）**：用视觉模型为每张图/表生成**详细文字描述**，把描述与原图一起入库；检索命中后把描述（或多模态模型看原图）交给 LLM。实现简单，最常用；
2. **多模态 Embedding**：用统一的多模态嵌入模型（图文同空间）直接对图像/页面截图做向量化，文本 query 可直接检索图片；命中后由多模态 LLM 理解原图生成答案；
3. **版面感知解析**：用文档理解模型（版面分析 + 表格结构还原）把 PDF 的布局、表格转成结构化 Markdown/HTML 再走普通文本 RAG——表格类信息的性价比之选。

**工程要点**：

- 命中图片时的生成端必须是**多模态模型**（能看图），或退而用 caption；
- 元数据同样关键：图题、所在章节、页码既是检索信号也是引用依据。

## 深度解析

- 方案选择逻辑：图表少、精度要求中 → Caption 方案最快；图表是核心信息源（财报、设计文档）→ 多模态 Embedding + 多模态生成；以表格为主 → 版面解析优先；
- 评估要按内容类型分层：纯文本题、图表题、混合题分别看命中与正确率——多模态 RAG 的退化往往先出现在图表题；
- 成本提示：多模态嵌入与多模态生成的单价高于纯文本，缓存策略更重要。
