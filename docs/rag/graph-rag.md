## 问题

什么是 GraphRAG？它解决了普通向量 RAG 的什么短板？

## 核心答案

- **定义**：在传统"向量检索"之外，引入**知识图谱/实体关系图**作为检索与组织层——从文档中抽取实体与关系建图，检索时沿图遍历、聚合社区摘要，再交给 LLM 生成。
- **普通 RAG 的短板（GraphRAG 的靶点）**：
  1. **多跳关联弱**："A 公司 CEO 的母校在哪"需要串联两个文档，点状 chunk 检索各自都"不够相关"；
  2. **全局性问题弱**："这个数据集的主要主题有哪些"需要全局概括，Top-K 局部片段拼不出全局图景；
  3. **关系型查询弱**："哪些供应商与被制裁实体有关联"本质是图遍历，向量相似度不擅长。
- **典型流程**：文档 → 实体/关系抽取（LLM）→ 建图 + 社区聚类 → 社区摘要 → 查询时"向量检索 + 图遍历/社区摘要"混合 → 生成。

## 深度解析

- 代价要主动讲：建图阶段需要大量 LLM 抽取调用（成本高、周期长），图谱维护有持续的更新成本——**收益集中在多跳与全局型问答**，普通 FAQ 没必要上；
- 实践形态常是"向量 + 图"双通道：点状问题走向量，关联/全局问题走图，由路由或 Agent 决定；
- 面试定位：知道它解决什么、贵在哪、什么时候不用，比背流程更加分。
