## 问题

上了 RAG 之后模型还是会幻觉，为什么？系统性处理方案有哪些？

## 核心答案

**RAG 后仍幻觉的原因**：

1. **检索失败被掩盖**：没检到相关内容，模型照样基于「看似相关」的噪音资料编；
2. **资料冲突**：库里新旧版本/矛盾文档同时命中，模型随意取舍；
3. **生成越界**：模型在资料基础上「合理外推」，补充了资料里没有的细节；
4. **资料本身错**：知识库内容有错，RAG 忠实传播错误。

**系统性处理方案（分四道防线）**：

1. **检索侧**：确保「检得到」——切分/混合检索/重排优化；设置**相关性阈值**，检索分数不足直接走拒答或澄清，而不是硬答；
2. **Prompt 侧**：强约束「仅根据资料回答；资料不足以回答时明确说不知道；引用来源编号」，并允许拒答；
3. **生成侧**：低温采样；要求**行内引用**（每句话标注依据的 chunk）便于校验；
4. **校验侧**：自动忠实度检查（答案与引用资料比对）、关键事实回查、人工抽检高危场景。

## 深度解析

- 「拒答是特性不是缺陷」：产品上把「资料未覆盖」设计成正常路径（引导人工/换个问法），比编一个答案的体验和风险都好；
- 冲突处理需要知识库治理：文档带版本/时效元数据，检索时过滤过期版本，源头减少矛盾资料；
- 评估要分开看：忠实度差 → 生成越界（管 Prompt/校验）；Context Precision 差 → 检索问题（管检索链路），归因清楚再动手。
