## 问题

RAG 和微调的本质区别是什么？什么场景该用哪个？

## 核心答案

**本质区别一句话**：RAG 是**外挂知识**（改输入），微调是**内化能力**（改参数）。

- RAG：知识放在外部库，运行时检索注入。知识可以随时更新、可溯源，但模型的行为模式不变；
- 微调：用数据更新模型权重，改变模型的**行为**——输出风格、任务格式、领域话术、指令遵循。知识更新要重训，且难溯源。

**选型决策树**：

```text
问题是「知识不够」？（内容新/私有/常变）
  → RAG
问题是「表现不对」？（格式、语气、领域术语、任务能力）
  → 微调
两个都有？
  → 组合：微调领域基座 + RAG 供知识（生产常见形态）
```

**典型误判**：想用微调「教模型最新产品知识」——知识一变就要重训，成本高还容易幻觉；这类需求全部应转 RAG。

## 深度解析

- 微调的真实成本：训练数据准备与清洗、算力、评估回归、版本管理，且每次知识更新重付一遍；
- RAG 的真实成本：检索链路工程（切分/索引/重排）、知识库运营、检索质量持续优化；
- 反直觉点：微调后模型对参数内知识的引用仍会幻觉（它只是「统计上学过」），RAG 的引用可点开核对——合规审计场景 RAG 近乎必选。
