## 问题

纯向量检索有什么问题？混合检索怎么解决？RRF 是怎么融合两路结果的？

## 核心答案

**纯向量检索的问题**：

1. **精确匹配弱**：专有名词、产品型号、错误码、人名等「字面即答案」的 query，语义向量反而模糊（“ERR_0x80070005”这类 token 分不清）；
2. **领域外语义漂移**：术语密集领域，通用 Embedding 距离不可靠；
3. **对短 query 的歧义**：语义泛化过头，召回「意思沾边但不对」的内容。

**混合检索（Hybrid Search）**：**BM25（关键词/稀疏检索）+ 向量（语义/稠密检索）双路召回，融合排序**。

- BM25：基于词频与文档长度的经典打分，强在精确词匹配、术语检索；
- 向量：强在语义等价（换说法也能召回）；
- 两路互补，各自召回 Top-K 后融合。

**RRF（Reciprocal Rank Fusion）**：按「排名」融合，不比分数绝对值：

```text
RRF 评分(d) = Σ over 检索路 [ 1 / (k + rank_i(d)) ]    # k 常取 60
```

- 每路检索把候选文档按名次打分（排第 1 得分最高），跨路求和后重排；
- 优点：两路分数量纲不同也能融合、无需调参拟合分数、实现简单，是工程默认做法。

## 深度解析

- 更进阶的融合是**加权分数融合**（各路分数归一化后加权），可调出领域最优但要维护权重；
- 混合检索的生效前提是**分词与语义各自正确**：中文 BM25 要配好分词器；向量路要确认 Embedding 对专有名词的表现；
- 效果验证方法：构建含「关键词型」「语义型」两类 query 的评测集，分别看两路的命中率与融合后的提升。
