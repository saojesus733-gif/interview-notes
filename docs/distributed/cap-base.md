## 问题

来聊聊 CAP 理论。很多人张口就说"分布式系统只能三选二"，这种说法准确吗？
工程实践里大家天天讲的 BASE 理论，和 CAP 又是什么关系？

## 核心答案

- C（一致性）：所有节点在同一时刻看到的数据完全相同；A（可用性）：每个请求都能在有限时间内收到非错误的响应；
  P（分区容错性）：节点间发生网络分区时系统仍能继续运行。

- P 是必选项：分布式系统中网络故障无法避免，所以真实的取舍是"分区发生的那一刻，在 C 和 A 之间二选一"。

- CP 系统：分区时宁可拒绝部分请求也要保证数据一致，典型代表 ZooKeeper、etcd。

- AP 系统：分区时继续对外服务、允许读到旧数据，典型代表 Eureka、Cassandra。

- BASE 理论：基本可用（Basically Available）、软状态（Soft State）、最终一致（Eventually Consistent），是 AP 路线的工程化延伸。

- 常见误读：三选二不是永远放弃 C；没有分区时 C 和 A 可以兼顾，分区恢复后通过数据同步达成最终一致。

## 深度解析

- 底层原理：CAP 证明的是分区发生瞬间副本之间无法通信，此时要么返回旧数据（保 A），要么等待或拒绝请求（保 C），二者只能取其一。

- 追问点：为什么没有真正的 CA 分布式系统？因为只要跨节点部署就必然可能分区，CA 只在单机场景下成立。

- 追问点：ZooKeeper 不是分区时完全不可用——只要半数以上节点存活仍能服务；Eureka 的自我保护机制则是 AP 的典型体现。

- 常见误区：把"最终一致"当成"马上一致"，实际要接受一致性窗口内的短暂不一致，业务必须能容忍这段脏读期。

- 加分项：PACELC 理论补充了"无分区时一致性 A 与延迟 L 的权衡"，能主动提出来通常会让面试官眼前一亮。
