## 问题

秒杀或大促的流量瞬间打进来，怎么保证系统不被冲垮？
聊聊四种常见限流算法的原理和区别，单机和分布式限流又分别怎么做。

## 核心答案

- 固定窗口计数器：单位时间内计数超过阈值就拒绝，实现最简单；
  但窗口边界存在临界突刺，两个窗口交界处可能放过近两倍流量。

- 滑动窗口：把大窗口切成多个小格随时间滑动统计，临界问题明显缓解；格子越细精度越高，但统计成本也随之上升。

- 漏桶：请求先进桶，以恒定速率流出，桶满直接拒绝；输出绝对平滑、适合保护下游，但完全无法应对突发流量。

- 令牌桶：系统匀速往桶里放令牌，请求拿到令牌才放行；桶里积累的令牌允许一定的突发流量，是工程上的主流选择。

- 单机限流：Guava RateLimiter 是经典的令牌桶实现；Sentinel 支持 QPS、线程数等多种维度的流控规则。

- 分布式限流：用 Redis + Lua 把计数逻辑原子化，集群共享统一限额；通常网关层做第一道防线，服务内再做细粒度限流。

## 深度解析

- 底层原理：Lua 脚本在 Redis 单线程模型下原子执行，"读-判断-写"三步不会被并发打断，
  这是分布式限流正确性的关键。

- 追问点：被限流的请求怎么处理？快速失败返回 429 或降级数据，而不是排队等待，否则限流本身反而拖垮服务线程。

- 追问点：限流位置怎么分级？网关做粗粒度全局限流，服务内部按接口分级，核心接口阈值高于非核心，规则要支持动态下发。

- 常见误区：混淆漏桶和令牌桶——漏桶限制的是流出速率（恒定），令牌桶限制的是平均速率（容忍突发）。

- 延伸：集群容量约等于单机阈值乘以实例数，分布式限流和单机限流通常两层叠加使用，互为兜底。
