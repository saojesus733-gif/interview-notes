## 问题

三台缓存机器扩到四台时，为什么普通取模会导致缓存几乎全部失效？
一致性哈希是怎么解决这个问题的？虚拟节点又是干什么的？

## 核心答案

- 普通取模的问题：hash(key) % N，N 从 3 变 4 后几乎所有 key 的落点都变了，
  缓存大面积失效会引发缓存雪崩。

- 哈希环：把哈希空间组织成 0 到 2^32-1 的环，节点和 key 都哈希映射到环上。

- 寻址规则：key 在环上沿顺时针找到的第一个节点，就是它的归属节点。

- 增删节点只影响相邻：新增节点只接管环上它到前一节点之间的一段 key，其余数据不动，失效比例从"几乎全部"降到约 1/N。

- 虚拟节点：每个物理节点映射成上百个虚拟节点散布在环上，节点少时避免数据倾斜，还能按机器性能差异化加权。

- 应用场景：分布式缓存分片（Redis/Memcached 客户端）、负载均衡（相同请求路由到同一节点）、分布式任务分配。

## 深度解析

- 底层原理：普通取模的结果对 N 敏感，而一致性哈希的映射只依赖 key 与节点在环上的相对位置，
  节点变化只迁移一段弧的数据。

- 追问点：虚拟节点为什么能解决倾斜？真实节点少时在环上分布稀疏、各自负责的弧极不均匀；虚拟节点数量大，靠大数定律拉平。

- 追问点：与 Redis Cluster 的槽方案对比？Redis Cluster 用 16384 个固定槽做预分片，思路类似但迁移粒度更可控（按槽迁移）。

- 常见误区：以为一致性哈希下数据完全不动；节点变化仍会迁移约 1/N 的数据，只是迁移量可控且有界。

- 延伸：带负载上限的一致性哈希（有界负载）和跳变哈希（Jump Hash）是进阶变体，简单提一句即可加分。
