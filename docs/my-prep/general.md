# 通用拷打点 — 追问准备册（含参考答案）

> 跨项目的通用问题，来自真实面经里出现频率最高的"送命题"。答案给了口径框架，**带【】的必须换成你的真实信息**。

## 一、开场与背景

**1. 自我介绍**

30 秒版（可直接用）：
> 面试官好，我是数据科学与大数据技术专业的应届生，方向是 AI 应用开发。实习做过企业办公 AI 助手——制度问答 RAG 加受控 Agent Tool，还有配套的数据同步管道。自己主导了两个项目：一个是 LangGraph 做的多子图租房 Agent，亮点是 interrupt 中断恢复和 LLM 生成 SQL 的校验链路；一个是多模态穿搭应用 AIWear，CLIP 跨模态检索加 Qwen-VL 图片编辑，已经部署在云服务器上。我擅长的就是把大模型能力包成可靠的后端服务，来面试也是想在这个方向继续深入。

2 分钟版：在上面基础上，每个项目展开讲一个"最硬的细节"（实习讲死信+对账机制；智居讲 interrupt 三段式；AIWear 讲 Redis 向量的权衡与 pgvector 演进），收尾加一句求职动机。

**2. 本科为什么这个专业？为什么做 AI 应用？**

参考口径：数据科学本身就是"数据 + 建模"的专业，学下来发现真正的杠杆在把模型接进真实业务——所以往 AI 应用开发走，课程里数据库、大数据组件的学习也正好支撑了后面做数据管道和 RAG 知识库。【补一句你的真实触发点，如某个课/某个项目让你转向的】

**3. 2027 届，实习和秋招时间冲突吗？**

参考口径：大四课程已基本修完，可以全职实习/投入秋招准备；实习期间的项目会持续迭代，不是做完就扔。

## 二、项目角色与分工（字节原题，必问）

**4. 你在项目里承担什么角色？团队几个人？做了多久？**

准备原则：**如实切分，不夸大**。参考切分口径【按实际修改】：
- 实习：团队 X 人，我负责【受控 Tool 边界设计 + 数据同步可靠性机制】这两块的落地
- AIWear：个人项目（或 X 人分工），我负责全部后端与 AI 链路
- 智居 Agent：个人项目，从架构到部署独立完成
面试官会用三连追问验证（"这个模块谁写的""为什么这么设计"），所以切分必须真实。

**5. 为什么不用 Claude Code / 为什么不用某个现成框架？**（字节原题）

参考口径：分两层——实习项目按团队既有技术规范走，自研可控性优先（制度问答容错低）；个人项目本质是学习目的，**自己搭 runtime 才能讲清工具调用、状态管理、中断恢复这些机制**，用现成的反而失去了面试时的深度。对 Claude Code 的态度是积极的：开发过程用它提效，但核心链路自己写。

## 三、AI 编程与质量（简历写了熟悉 Claude Code，必被问）

**6. 用 AI 写代码，你会看它生成的代码吗？怎么保证质量？** ⭐3（恒润候选人真挂在这题）

参考答案：会看，而且有固定清单——①**逻辑正确性**：对照需求逐段读，重点看它"脑补"了不存在的接口或字段；②**边界与异常**：空值、超长输入、失败分支是不是处理了；③**安全**：SQL 拼接、敏感信息进日志这类；④改完必跑：接口用实际请求打一遍，数据操作用小数据集验证。关键决策（架构、存储选型）从不外包给 AI——AI 出方案，我做决策。这样答既有方法又显示判断力。

**7. 如何确保迭代时 AI 改的地方是真的有效？**（字节原题）

参考答案：靠回归——把踩过的问题沉淀成坏例集，每次改动后先跑坏例集确认旧的没退化，再跑主流程；上线前灰度给小范围用户。核心思想：**用评测对抗不确定性**。参考 [AI 迭代与评测护栏](/evaluation-deployment/ai-iteration-evaluation-guardrails)。

## 四、综合压力题

**8. 三个项目里哪个最难？难在哪？**

建议选智居 Agent 的中断恢复：难点在"会话状态的生命周期管理"——interrupt 暂停点的设计、checkpoint 的恢复语义、防重复提交的状态复位，每个都要想清楚。讲难点的目的不是诉苦，是展示你理解问题的深度。

**9. 如果重来一次，会改哪个技术决策？**

建议口径（真实且加分）：AIWear 的向量存储一开始就会评估 pgvector 而不是先上 Redis——不是说 Redis 错了，而是如果一开始就预期数据增长，省一次迁移。这答案展示"知道边界在哪"，比"都很完美"可信十倍。

## 五、反问环节（准备 3 个）

- 这个岗位入职后前三个月主要做什么？有没有导师带？
- 团队现在 AI 应用落到什么阶段了，最大的瓶颈是模型还是工程？
- 以我的背景，您觉得入职前最适合补强哪一块？（把"评价我"变成"请教他"）
