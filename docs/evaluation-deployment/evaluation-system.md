## 问题

LLM 应用无法用传统单测完全覆盖，如何建立系统的评估体系？

## 核心答案

**三层评估 + 一条业务锚线**：

1. **自动指标层**（快、便宜、可回归）：
   - 确定性任务：精确匹配/格式校验/规则断言（如 JSON Schema 通过率）；
   - 相似度类：BLEU/ROUGE 对标准化答案（有局限，仅辅助）；
   - 检索类：Recall@K、MRR；
2. **模型评 layer（LLM-as-a-Judge）**：用强模型按评分细则（rubric）给开放性回答打分——忠实度、相关性、有用性；可规模化跑回归集；
3. **人工评估层**（准、贵、校准用）：抽检校准 Judge、评估新场景、争议样本仲裁；
4. **线上业务指标**（最终裁判）：任务完成率、人工转接率、用户采纳/编辑率、CSAT、投诉率。

**工程化落地**：

- **评估集是核心资产**：覆盖典型场景 + 边界 case + 历史坏例，版本化管理；
- **每次变更必回归**：改 Prompt/换模型/调检索参数 → 跑评估集，看通过率与分项指标；
- **线上采样回流**：生产流量抽样进评估集，防「评估集过时、线上退化」。

## 深度解析

- 评估体系决定迭代速度：有回归评估的团队可以放心高频迭代 Prompt，没有的团队每次改动都是赌博；
- 分层归因：指标差先分「检索错/生成错/格式错」再优化，避免全局瞎调；
- 防过拟合评估集：定期换血 + 留出隐藏测试集，防止针对评估集的「应试优化」。
