## 问题

私有化部署 LLM 时，量化（INT8/INT4）能带来什么？边缘部署怎么做？

## 核心答案

**量化（Quantization）**：把模型权重（及激活/KV Cache）从 FP16 等高精度压到 INT8/INT4 等低位宽存储与计算。

- **收益**：显存占用大幅下降（INT4 约为 FP16 的 1/4）→ 单卡能装更大模型或更大 batch；带宽压力小 → 推理速度提升；成本下降；
- **代价**：精度有损，任务表现可能下降（复杂推理比简单任务更敏感），需要用评估集回归验证；
- **主要路径**：
  - **PTQ（训练后量化）**：直接对训好的模型量化，成本最低（GPTQ、AWQ 等方法）；
  - **QAT（量化感知训练）**：训练中模拟量化误差，精度更好但成本高；
- **实践建议**：优先 INT8（几乎无损）→ 效果可接受再试 INT4；务必对比量化前后在自家任务上的指标。

**边缘部署**（端侧/本地设备运行）：

1. **模型小型化**：小参数量模型 + 蒸馏（大模型教小模型）+ 剪枝；
2. **压缩与加速**：INT4/NF4 量化、推理引擎优化（ONNX Runtime、llama.cpp 类、移动端 NPU 加速）；
3. **架构补偿**：端侧小模型做意图识别/草稿，复杂任务上传云端大模型（端云协同/投机解码思想）；
4. **约束清单**：内存/存储预算、功耗与发热、离线能力、模型更新通道。

## 深度解析

- 显存账要会算：权重显存 ≈ 参数量 × 每参数字节数（FP16=2B、INT8=1B、INT4≈0.5B），再加 KV Cache 与激活——「7B 模型 FP16 约 14GB 起步」这类估算面试常问；
- 量化不是免费的：需评估的不只是准确率，还有长文本能力、工具调用格式的稳定性（低位宽下更易抖）；
- 服务端量化（省显存提吞吐）与边缘量化（塞进设备）目标不同，方法与评估侧重点也不同。
