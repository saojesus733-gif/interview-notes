## 问题

Agent 能调用工具、操作外部系统，安全与权限上要怎么设计？

## 核心答案

**核心思想：模型是「不可信的建议者」，权限与执行必须收敛在确定性代码里。**

**权限设计**：

1. **最小权限**：每个 Agent/工具只授当前任务所需的最小权限集，按 Agent 分域（客服 Agent 看不到财务工具）；
2. **身份透传**：Agent 代表用户操作时以用户身份执行（on-behalf-of），权限随人走，不用超级服务账号；
3. **静态白名单 + 动态风控**：工具白名单之外一律拒绝；叠加动态检查（参数范围、频率、金额阈值）。

**执行安全**：

1. **参数校验**：Schema 约束 + 业务校验双层，永不信任模型输出的参数；
2. **写操作加固**：幂等 key、二次确认（参数回显让用户确认）、高危操作 HITL 审批；
3. **沙箱执行**：代码执行类工具在隔离环境（容器/无网沙箱）中运行，限制文件与网络访问；
4. **注入防御纵深**：输入/内容过滤、指令数据隔离、出站信息过滤（防 Prompt 注入拖库），见 [Prompt 注入防御](/prompt-engineering/prompt-injection-defense)；
5. **数据安全**：进入模型上下文前脱敏（PII/密钥），上下文日志加密分级存储，遵守保留期限。

**审计与运营**：全量工具调用留痕（谁/何时/参数/结果）、异常行为告警、定期红队演练、事故复盘进护栏清单。

## 深度解析

- Agent 安全 = 传统安全 + 模型特有风险：传统部分（鉴权、最小权限、审计）照旧严格做，特有部分（注入、幻觉驱动的错误操作、上下文泄露）用「确认-审批-沙箱-过滤」补位；
- 设计检验法：假设模型被完全攻骗（输出任意工具调用），系统能否守住不发生资损/越权？能守住，权限设计才合格；
- 权限粒度建议到「工具 + 参数模板」级别：同一工具不同参数范围可以不同权限（查订单 vs 退款）。
