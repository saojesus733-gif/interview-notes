## 问题

Agent 是多步、动态、带工具调用的系统，怎么评估它的效果？和评估单轮 LLM 输出有什么不同？

## 核心答案

**与单轮评估的三大不同**：结果依赖过程、路径不唯一、失败可发生在任何一步——所以要**拆开评估**。

**四个评估层次**：

1. **端到端结果**：任务完成率（相对标准答案/人工判定）——最终业务指标；
2. **轨迹（Trajectory）评估**：过程对不对——
   - 工具选择：该调的工具调了吗？有没有乱调？
   - 调用顺序与参数：合法且最优吗？
   - 步数效率：几步完成？与最优路径差多少（成本）？
3. **单步能力评估**（组件级、可离线回归）：
   - 规划质量：计划是否覆盖目标、拆解是否合理；
   - 工具调用准确率：给定场景，选对工具/传对参数的比例；
   - 记忆与检索命中；
4. **成本与稳定性**：平均 token/延迟/失败率/循环率——Agent 评估离不开资源维度。

**评估方法**：

- **模拟环境**：构造可控工具（mock API + 种子数据），让可复现的"考题"批量跑；
- **LLM-as-a-Judge 评轨迹**：按 rubric 给过程打分（选工具是否合理、推理是否偏离），人工抽检校准；
- **真实流量回流**：线上失败任务的轨迹进回归集。

## 深度解析

- 关键工程判断：端到端通过率是最准的但太贵太慢，组件级评估最便宜但不能保证组合正确——**分层组合**：日常回归靠组件级 + 小集端到端，发版前跑全量端到端；
- 轨迹评估注意"路径不唯一"：同一任务可有多种正确解法，判分对象是"过程合理性"而非"复刻标准路径"；
- 加分点：把失败轨迹按环节归因（规划错/选错工具/参数错/工具本身失败/总结错）形成看板——Agent 迭代的方向感来自这里。
