## 问题

LLM 应用的 API 费用暴涨，有哪些系统性的成本优化手段？

## 核心答案

**按杠杆大小排序**：

1. **模型分级路由（最大杠杆）**：意图分类/简单抽取/格式化任务 → 小模型；复杂推理 → 旗舰模型。多数流量不需要最强模型，价格差可达数十倍；
2. **缓存**：
   - 精确缓存：相同请求直接返回；
   - 语义缓存：相似问题命中（向量化匹配历史 QA）；
   - Prompt 前缀缓存：稳定前缀（System/few-shot/长文档）复用，推理侧省钱省延迟；
3. **上下文瘦身**：RAG 资料按需精简（Rerank 后取 Top-N）、历史裁剪摘要、工具结果不整段进上下文——输入 token 是账单大头；
4. **输出控制**：合理的 max_tokens、要求精炼输出（输出 token 单价更高）；
5. **批处理与异步**：非实时任务走批处理 API（主流厂商半价左右）；
6. **架构级**：高频 FAQ 走传统检索/规则，不上模型；自部署承接稳定大流量（与 API 成本做盈亏平衡测算）。

**治理机制**：按租户/功能的 token 计量分账、预算与配额告警、异常用量检测（循环调用、Prompt 失控膨胀）。

## 深度解析

- 成本优化的前提是**可归因**：网关层按「业务功能 × 模型 × 请求类型」打标计量，先看清楚钱花在哪，再谈优化；
- 与质量联动：每次降本动作（换小模型/砍上下文）都要跑评估集对比，防止「省钱省到退化」——成本与质量要一起进看板；
- 典型经验值：语义缓存 + 模型分级两项通常能砍 40%+ 账单，且不牺牲核心体验。
