## 问题

讲一个你做过的最困难的技术决策。你是怎么权衡的？

## 核心答案

**答题框架（决策四段式）**：

1. **背景与约束**：什么业务场景、卡脖子的是什么（时间/成本/技术条件）、有哪些硬约束；
2. **候选方案与权衡**：至少 2~3 个真实选项，讲清各自的代价，不只是优缺点罗列（用表格思维：性能/成本/团队熟悉度/可维护性）；
3. **决策依据**：为什么选它——最好有数据或小规模实验支撑，说清"在什么前提下这个选择成立"；
4. **结果与复盘**：验证了哪些判断、哪些判断错了、如果重来会怎样。

**选材建议**（对齐 AI 应用方向的决策类型）：

- 用成熟框架 vs 自研轻量编排（LangGraph vs 手写状态机）
- RAG vs 微调的路线路径
- 大模型 API vs 私有化部署
- 同步生成 vs 异步任务化

## 深度解析

- 面试官考察的是决策质量而非结果完美：有依据的取舍 + 诚实的复盘 > "我选了正确的方案"；
- "在什么前提下成立"这句是高级感所在——技术决策几乎都是情境相关的，承认边界反而可信；
- 避免：事后诸葛式包装（把当时没想清楚的说是深思熟虑）、把团队决策完全说成个人功劳（"我推动并执行了"比"我一个人决定了"更真实）。
