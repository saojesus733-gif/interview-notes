## 问题

"介绍一下你做过的最有挑战的项目"——怎么讲项目才能经得起层层深挖？

## 核心答案

**STAR 三层版本，先备好再上场**：

- **30 秒版**：一句话背景 + 一句话职责 + 一句话量化结果（用于自我介绍带出）；
- **3 分钟版（标准 STAR）**：
  - **S 情境**：业务背景与问题，一两句讲清"为什么这事重要"；
  - **T 任务**：你的职责边界与目标（有量化：QPS、成本、通过率）；
  - **A 行动**：挑 2~3 个关键技术决策讲，每个都按"选项 → 权衡 → 为什么选它"展开；
  - **R 结果**：量化指标 + 一句反思（还能做得更好的地方）；
- **15 分钟深挖版**：把 A 里的每个决策展开成完整的备选方案对比表，准备好白板画架构图。

**LLM 项目的结果要双轨**：效果指标（评估集通过率、解决率）+ 工程指标（P99 延迟、单次成本）——AI 项目只讲一个维度会被追问穿。

## 深度解析

- 面试官深挖的标准路径：你说"做了检索优化"→ 为什么做 → 怎么量化问题 → 方案对比 → 落地效果 → 还能怎么优化。每个节点都要有下一层答案；
- **失败的尝试也要准备 1~2 个**："试过 X 方案不行因为 Y"是加分项，全是成功反而显得不真实；
- 数字必须真实且能解释口径（"P99 从 2s 降到 800ms，口径是……"），编的数字经不起追问口径。
