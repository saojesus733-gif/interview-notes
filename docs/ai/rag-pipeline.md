## 问题

什么是 RAG？完整的执行流程是怎样的？为什么需要 RAG？

## 核心答案

RAG（Retrieval-Augmented Generation，检索增强生成）= 先检索、后生成：让模型回答前先从外部知识库中召回相关资料，把资料拼进 Prompt 再生成答案。

完整流程分两个阶段：

**离线索引**：

1. 文档加载与清洗（PDF / HTML / 数据库等）；
2. 切分（Chunking）成小块；
3. 用 Embedding 模型把每个 chunk 向量化；
4. 写入向量数据库（建立索引）。

**在线问答**：

1. 用户提问，查询同样向量化；
2. 向量库召回 Top-K 相似 chunk（可先做查询改写/扩展）；
3. （可选）重排（Rerank）精排；
4. 把召回内容 + 问题组装成 Prompt；
5. LLM 生成答案，可附引用来源。

为什么需要 RAG：

- **知识时效性**：模型训练数据有截止日期，RAG 可接入最新/私有知识；
- **降低幻觉**：让模型「看着资料回答」，有据可依；
- **可溯源**：答案能附带出处，便于核验；
- **成本低于微调**：更新知识只需更新文档库，不用重训模型。

## 深度解析

- 切分策略：固定长度、递归字符切分、按标题/语义切分；chunk 太大召回不精准、太小上下文断裂，通常配 overlap 保留边界信息。
- 混合检索：BM25（关键词）+ 向量（语义）双路召回，用 RRF（倒数排名融合）合并，弥补纯向量检索对专有名词、编号类查询的短板。
- 重排：召回用双塔（快而粗），重排用 Cross-Encoder（慢而准），是效果与延迟的典型折中。
- 评估：检索侧看召回命中率 / MRR，生成侧看忠实度（是否忠于资料）与答案相关性，可用 RAGAS 等框架。
