## 问题

什么是大模型的幻觉？产生原因是什么？工程上有哪些缓解手段？

## 核心答案

**幻觉（Hallucination）**：模型生成的内容流利但与事实不符，或编造不存在的引用、API、数据。

成因（简化理解）：

1. 训练目标是「预测下一个词」，不是「输出真话」——流利 ≠ 正确；
2. 训练数据本身有错、有噪音，且知识有截止日期；
3. 超出模型知识范围时，模型倾向「顺着编」而不是承认不知道；
4. 采样随机性（温度越高越容易跑偏）。

缓解手段（分层）：

- **检索增强（RAG）**：让模型基于给定资料作答，最常用最有效；
- **Prompt 约束**：明确「仅根据资料回答，资料中没有就说不知道」；
- **降低温度**：事实型问答用低温度减少发散；
- **输出校验**：要求附引用并核验、自一致性投票（多次生成取多数）、用工具/规则复核关键事实；
- **对齐与微调**：用「拒答样本」训练模型学会说不知道。

## 深度解析

- 评估要区分两个维度：**忠实度**（Faithfulness，答案是否忠于给定资料）与**事实性**（Factuality，答案是否符合外部事实），RAG 场景更关注前者；
- 幻觉无法根除：概率生成模型的本质决定了只能「工程上压低」，高可靠场景必须外挂校验链路（规则、检索比对、人工审核）。
