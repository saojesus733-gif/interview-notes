## 问题

Function Calling 的完整流程是怎样的？模型在其中扮演什么角色？

## 核心答案

流程四步：

1. **注册工具**：应用把工具的名称、功能描述、参数 JSON Schema 随请求发给模型；
2. **模型决策**：模型判断是否需要调用工具，需要则输出结构化的调用意图（工具名 + 参数 JSON），**模型只输出意图，不真正执行**；
3. **应用执行**：应用代码解析参数、实际调用工具（查库 / 调 API / 跑代码），拿到结果；
4. **结果回传**：把执行结果作为新消息发给模型，模型基于结果继续生成最终回答（也可能再次发起工具调用）。

关键认知：**执行者永远是应用程序，模型只负责「决定调什么、传什么参数」**。

## 深度解析

- 工具描述质量决定调用准确率：name、description、参数说明写不清，模型就会错调或编参数；
- 参数由 JSON Schema 约束，部分模型支持约束解码保证格式合法；现代 API 支持一次并行调用多个工具；
- 工具太多时可通过先做工具检索（只把相关工具放入上下文）降低干扰；
- MCP（Model Context Protocol）等协议在做的事：把「应用-工具」的对接标准化，工具写一次多处可用。
