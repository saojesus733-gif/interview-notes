## 问题

什么是渐进式披露？它解决 Agent 系统中的什么问题？

## 核心答案

- **定义**：不把全部信息一次性塞进上下文，而是**分层组织、按需加载**——模型先看到最小必要信息，需要更多时再显式加载下一层。
- **典型分层**：

```text
第一层：目录/索引（工具清单概览、文档目录、技能列表）——常驻上下文
第二层：摘要（某工具的详细用法、某文档的核心结论）——按需加载
第三层：全文（完整文档、工具返回原始数据）——明确请求时才读
```

- **解决的问题**：
  1. 上下文预算有限，全量注入不可行；
  2. 工具/文档太多时，全列出来会互相干扰，模型选择准确率下降；
  3. 无关信息稀释注意力，降低决策质量。

- **Agent 场景的落点**：工具数量多时先给「工具目录」，模型选定后再注入该工具的完整 Schema；知识库问答先给文档标题与摘要，模型指定后再读全文。

## 深度解析

- 本质是 Context Engineering「选择」策略的结构化：把「给什么」从一次性决策变成多步决策，用「多一次调用」换「上下文干净」。
- 与 RAG 的关系：RAG 是按语义选内容，渐进式披露强调分层加载的**信息架构**——两者常组合（检索命中 → 先给摘要 → 需要再取全文）。
- 成本权衡：多一层披露多一轮调用；信息层级要按「命中率 × 单价」设计，高频信息别放太深。
