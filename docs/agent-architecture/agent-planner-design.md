## 问题

设计 Agent 的规划器时，如何避免「路径震荡」——计划反复推翻、执行原地打转？

## 核心答案

**路径震荡的典型表现**：

- Plan 每执行一步就被整体推翻，永 unstable；
- Agent 在两个动作间来回横跳（查 A → 查 B → 再查 A）；
- 无限重试同一失败动作。

**设计对策**：

1. **计划与执行分离 + 计划固化**：Plan 产出结构化步骤列表后**冻结**，执行器只负责推进；重规划必须是显式触发的独立决策，而不是每步都顺手改计划；
2. **明确的 Replan 触发条件**：只有「步骤失败且重试无望」「出现推翻前提的新信息」「用户改变目标」才允许重规划，并限制重规划次数；
3. **状态与进度追踪**：维护步骤完成度与关键结论，让模型「看得见自己走到哪」，避免重复劳动；
4. **震荡检测器（护栏）**：统计连续动作序列，检测重复/回环（如同一工具同参数连续调用），命中则强制注入纠偏提示或升级人工；
5. **预算与终止**：最大步数、最大 token、最大工具调用数，硬上限兜底。

## 深度解析

- 震荡的技术根源：上下文里历史动作占比越来越大，近期失败观察反复刺激模型「换个试试」，而全局目标被稀释——本质是 Context Engineering 问题，规划器要把「目标 + 进度」固定在上下文显著位置。
- 把计划存为数据（checklist 状态表）而非纯文本，执行器按结构化状态推进，天然可恢复、可审计。
- 经验：执行器每完成一步输出「进度报告」（完成/失败/结论），是对抗震荡性价比最高的手段。
