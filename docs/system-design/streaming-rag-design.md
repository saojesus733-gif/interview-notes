## 问题

设计一个流式 RAG 问答：用户提问后逐 token 看到答案，还要能显示"正在检索什么"。检索和生成怎么衔接？有什么并行优化的空间？

## 核心答案

**主链路（事件流设计）**：

```text
用户提问 → [status 事件: 正在理解问题]
        → query 改写 → 多路检索并行（向量+关键词）
        → [status 事件: 已找到 N 条相关资料]
        → Rerank → 拼 Prompt → LLM 流式生成
        → [token 事件 × N] → [done 事件: 引用列表]
```

- 前端一条 SSE 连接收多种事件：status（过程面板）、token（打字机）、done（引用与完成标记）。

**并行的真实空间（易错点）**：

1. **可以并行的**：多路检索并行、query 改写与检索准备并行、生成期间的**下一步**预处理；
2. **不能并行的**：检索结果没回来就"开始生成答案"——依据都没有，只能输出空话（幻觉温床）；检索必须先于生成完成；
3. 首字延迟 = 检索延迟 + LLM TTFT，两段分别优化：检索缓存/ANN 调优、模型就近部署/前缀缓存。

**引用与展示**：引用在生成后统一附（带来源标题与段落定位），或 token 流中嵌引用标记由前端渲染；过程面板展示检索到的资料标题，提升可解释性与等待体验。

**稳定性**：检索超时降级（只用已返回的一路结果）、生成中断续传（呼应流式稳定性）、事件 ID 支持断线重连。

## 深度解析

- 加分点：过程事件的用户体验价值——把 2~3 秒的检索等待变成"看得见的工作"，配合打字机把总感知延迟压到最低；
- 雷区：为了"流式"先吐客套话再等检索结果；引用不做定位（用户无法核验，信任崩塌）；
- 呼应：SSE 技术细节、企业级 RAG 的缓存与降级、流式稳定性三题。
