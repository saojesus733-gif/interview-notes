## 问题

设计一个 Agent 的长期 Memory 管理系统：记忆怎么存储、怎么检索、怎么处理时间衰减？用户的三个月前的偏好和昨天的对话都要能正确利用。

## 核心答案

**一、存储分层**：

- **事实条目**（结构化，MySQL）：用户画像、关键属性——Schema：`{id, 内容, 类型, 实体, 时间戳, 来源会话, 置信度, 有效期}`；
- **语义记忆**（向量库）：可检索的经验与偏好描述；
- **会话归档**（对象存储/库表）：完整 Chat History，只做审计与回溯原料。

**二、写入管道**（写路径与读路径分离）：

1. 会话结束/周期性触发 → LLM 从对话中**抽取候选记忆**（只留值得记的事实）；
2. 与现有记忆**比对合并**：相似度高的判定"新增 / 更新（信息变了）/ 冲突（保留两者带时间戳）"；
3. 异步写入，不阻塞主链路。

**三、检索**：按当前任务语义 Top-K，排序 = 语义相关度 × 时效权重 × 重要度；命中后注入上下文并标注来源时间。

**四、时间衰减**：

- 记忆打分 = 初始重要度 × 衰减函数（半衰期思想：随时间指数衰减）；
- **保护名单**：身份证、长期偏好等"持久事实"标记为不衰减；
- 衰减到阈值的记忆降权/归档而非物理删除（可恢复）。

**五、治理**：用户可查看/修改/删除自己的记忆（合规），全量变更留痕。

## 深度解析

- 加分点：读多写少的优化——抽取与合并是异步离线任务；记忆质量的评估（有记忆 vs 无记忆的任务成功率 A/B）决定这套系统是否值得；
- 可复用开源思路：Mem0 的抽取-合并管道、Zep/Graphiti 的时序有效性建模（呼应长期记忆框架题）；
- 雷区：只存不衰减（噪音淹没关键记忆）；只衰减无保护（关键事实被遗忘）；原始对话直接当记忆（检索质量差）。
