## 问题

Agent 执行高危操作前需要人工审批，Human-in-the-Loop 机制怎么设计与实现？

## 核心答案

**设计原则**：审批是**流程中的一等节点**，不是异常补丁——在图/工作流中显式建模「挂起-审批-恢复」。

**实现机制**：

1. **挂起点定义**：工具/节点声明「需要审批」（按操作类型：转账、删除、外发；或按风险分数动态触发）；
2. **状态持久化**：命中审批时，把当前执行状态（上下文、待执行动作及其参数）写入检查点，**释放执行资源**；
3. **通知与界面**：推送审批请求（附上下文摘要 + 待执行动作详情）给审批人，前端展示可接受/修改/拒绝；
4. **恢复执行**：审批结果作为输入注入，从检查点恢复继续执行；拒绝则走终止/重规划分支；
5. **超时与升级**：审批超时按策略处理（自动拒绝/升级到上级/挂起提醒），防止流程死等。

**流程示意**：

```text
Agent 决策 → 调用"转账"工具 → [拦截：高危操作]
  → 状态落库挂起 → 通知审批人
  → 批准 → 恢复执行工具
  → 拒绝 → 回到 Agent（带"用户拒绝"观察），改道或终止
```

## 深度解析

- 审批粒度权衡：每步都审（人变成瓶颈）vs 只审高危（剩余风险），通常按「写操作 + 资金 + 外发」三张清单圈范围，配合参数阈值（金额上限）动态触发；
- 上下文传递：审批人需要看到「为什么做这个动作」——把 Agent 的决策依据与检索证据一起展示，审批质量才高；
- 体验优化：批量预授权（同会话同类低危操作一次授权）、事后抽审替代事前审批（低风险高频场景），在控制风险与效率间找平衡。
