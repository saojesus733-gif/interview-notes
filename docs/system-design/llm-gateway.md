## 问题

多个业务都要用 LLM，如何设计一个统一的 LLM Gateway？

## 核心答案

**为什么需要**：业务直连模型厂商会导致——密钥散落、无法统一限流计费、模型绑死、重复造缓存与监控。网关把 LLM 变成「企业内部的一项受治理的基础设施」。

**核心功能模块**：

1. **统一协议层**：内部统一 API（消息格式、工具调用、流式），适配层对接多家厂商/自部署模型——业务无感切换模型；
2. **路由策略**：按任务类型/成本/能力/灰度规则路由（如：结构化抽取→小模型，复杂推理→旗舰模型）；
3. **安全治理**：密钥集中管理、租户鉴权、配额与限流（按租户/接口分级）、敏感信息（PII）检测与脱敏、内容审计；
4. **成本中心**：token 计量计费、按租户/业务分账、预算告警；
5. **可靠性**：超时、重试（幂等）、多厂商 failover、熔断降级；
6. **优化层**：精确/语义缓存、Prompt 前缀复用、批处理调度；
7. **可观测**：全量调用日志、延迟/token/成功率大盘、trace 贯穿到业务会话。

**关键设计权衡**：

- 流式透传：网关必须支持 SSE 透传且不缓冲整个响应；
- 重试要小心非幂等（已部分输出的流式响应不可简单重试）；
- 协议演进：兼容 OpenAI 风格 API 已成事实标准，新厂商用适配器收编。

## 深度解析

- 网关是「模型资产化管理」的落点：模型路由表 + 评估基线放网关层，新模型上线先影子流量对比再放量；
- 与业务 Agent 的分工：网关管「调一个模型」的治理；Agent 编排层管「多步任务」——不要把业务逻辑下沉进网关；
- 合规审计价值：出域内容统一检测、留痕，是金融/政务场景必须项。
