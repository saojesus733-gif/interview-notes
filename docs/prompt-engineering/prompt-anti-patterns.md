## 问题

写 Prompt 有哪些常见的反模式？系统性调优 Prompt 的方法是什么？

## 核心答案

**常见反模式**：

1. **指令堆砌且互相冲突**：规则越写越多，后写的覆盖先写的，模型随机遵循其中一部分；
2. **负面指令主导**：满篇「不要 XX」，模型对「做什么」反而没有清晰目标——应改为正面描述期望行为；
3. **示例与要求不一致**：嘴上要 JSON，示例却是自由文本，模型跟着示例走；
4. **把礼貌当技巧**：如「请你务必、求求你」等情绪化措辞收效甚微，清晰度远比语气重要；
5. **无关上下文堆料**：塞大量背景材料稀释注意力，关键指令被淹没；
6. **一条 Prompt 扛所有任务**：多任务混杂，不如按任务拆分各自调优。

**系统调优方法**：

1. **建立评估集**：收集真实/典型输入 20~50 条，标注期望输出；
2. **单变量修改**：每次只改一处，跑评估集对比通过率；
3. **错误归因**：失败样本逐条分析——是指令歧义、缺示例、缺信息，还是模型能力不足（该换模型/加工具）；
4. **版本化 + 回归**：Prompt 进 git，改版跑回归，防止「修好一处坏两处」。

## 深度解析

- 「Prompt 工程的尽头是评估」：没有评估集的调优是凭感觉抽卡，有评估集的调优才是工程。
- 失败样本要区分「模型不会」与「Prompt 没说清」：前者靠换模型/微调/加工具，后者靠改 Prompt——混在一起调只会浪费时间。
- 与结构化输出配合：很多「不稳定」问题的根源是输出契约不严，优先加 Schema 约束再调措辞。
