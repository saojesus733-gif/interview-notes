## 问题

说一下你常用的 HTTP 状态码，301 和 302 有什么区别？502 和 504 通常是什么原因导致的？

## 核心答案

- **2xx 成功**：`200` 请求成功、`204` 成功但无响应体、`206` 断点续传的范围请求成功；
- **3xx 重定向**：`301` 永久重定向（浏览器会缓存、SEO 权重转移）、`302` 临时重定向（不缓存）、`304` 协商缓存命中；
- **4xx 客户端错误**：`400` 参数错误、`401` 未认证、`403` 已认证但无权限、`404` 资源不存在、`429` 请求过频限流；
- **5xx 服务端错误**：`500` 服务器内部异常、`502` 网关收到无效响应、`503` 服务暂不可用（过载/维护）、`504` 网关等待上游超时；
- `301` vs `302`：301 告诉浏览器「以后直接访问新地址」，搜索引擎更新收录；302 每次仍访问原地址，适合临时迁移；
- `304` 配合 `If-None-Match`（`ETag`）/`If-Modified-Since` 使用，命中则不传响应体，节省带宽。

`502` 与 `504` 的区别：502 是上游挂了或返回非法响应（如后端进程崩溃、被 kill）；504 是上游太慢、网关等待超时（如接口阻塞超过 Nginx 的 `proxy_read_timeout`）。

## 深度解析

- 追问点：强缓存（`200 from cache`）与协商缓存（`304`）的完整流程与优先级；`307/308` 与 301/302 的区别（不允许改请求方法）；
- 常见误区：`401` 与 `403` 语义（未登录 vs 没权限）；POST 经 302 重定向后可能被改成 GET；
- 排障思路：Nginx 报 502/504 时先看上游服务是否存活、日志与超时配置，502 通常是进程崩了，504 通常是慢查询拖住了；
- 追问点：`206` 与 `Range` 头配合实现断点续传与视频拖动播放，`416` 表示范围不合法；
- 常见误区：`204` 不是 `200` 加空响应体，它表示「无需返回内容」；`201 Created` 用于资源创建成功。
