## 问题

TCP 靠哪些机制保证数据不丢、不重、不乱序？请系统地梳理一遍，并说说每个机制各自解决什么问题。

## 核心答案

按「完整性、丢失恢复、节奏控制、连接管理」四个层面归纳：

1. **序列号 + 确认应答**：每个字节都有序号，接收方用 `ACK` 确认，同时完成去重与按序重组；
2. **校验和**：首部加数据一起计算，检测传输中的比特差错，校验失败直接丢弃，交给重传恢复；
3. **超时重传**：发出后启动定时器，超过 RTO 未收到 ACK 就重传，RTO 依据 RTT 平滑估算、自适应调整；
4. **快速重传与 SACK**：收到 3 个重复 ACK 立即重传；SACK 选项告知已收到的不连续区间，只补缺口，恢复更快；
5. **滑动窗口流量控制**：接收方通告 `rwnd` 限制发送速率，防止接收缓冲区被打满；
6. **连接管理**：三次握手同步双方初始序列号，四次挥手保证双方收发完毕后再释放，是以上一切的前提。

## 深度解析

- 可靠性三角：**序号**提供唯一标识、**确认**提供反馈、**重传**提供补救，三者缺一不可；
- 追问点：RTO 越小越好吗？太小会引发大量无谓重传、加重拥塞；TCP 用加权平均 RTT 加偏差估算，超时后指数退避；
- 常见误区：确认号表示「期望收到的下一个字节序号」，不是「已收到的最后一个字节」；
- 常见误区：TCP 可靠 ≠ 业务可靠，报文不丢不代表消息不重复，应用层仍需幂等与去重兜底。
