## 问题

这是一道几乎每场面试都会问的开放题：从浏览器输入 URL 到页面完整展示，中间都发生了什么？你会怎么组织这条主线？

## 核心答案

- **URL 解析与 DNS 解析**：查浏览器缓存 → 系统缓存 → `hosts` → 本地 DNS → 根/顶级/权威服务器，拿到目标 IP；
- **TCP 连接**：与服务器三次握手建立连接；
- **TLS 握手**（HTTPS）：协商加密套件、交换密钥、验证证书链；
- **发送 HTTP 请求**：构造请求行、请求头（含 Cookie、缓存字段）、请求体发出；
- **服务端处理**：负载均衡 → Web 服务器 → 应用逻辑 → 可能读写缓存与数据库 → 返回响应；
- **浏览器渲染**：解析 HTML 构建 DOM、解析 CSS 构建 CSSOM、合成渲染树 → 布局 → 分层绘制 → 合成显示，JS 执行可能阻塞解析；
- 连接复用（keep-alive）或四次挥手释放，页面完成展示。

追问点提示：每一步都能单独深挖——DNS 缓存层级、握手为什么三次、强缓存与协商缓存、渲染如何合成一帧。

## 深度解析

- 这题考察**知识体系完整性**：建议按「网络 → 服务端 → 渲染」三段展开，再让面试官挑方向追问；
- 追问点：HTTPS 站点可展开证书校验链、HSTS、TLS 会话复用；静态资源可展开 CDN 与多级缓存；
- 常见误区：只答渲染不答网络，或只背流程却说不清任何一步的原理，每个环节至少备一个可深挖的点；
- 性能角度延伸：DNS 预解析、HTTP/2 多路复用、`preload`/`prefetch` 都挂在这条链路上。
