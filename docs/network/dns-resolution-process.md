## 问题

描述一次完整的 DNS 解析过程，递归查询和迭代查询有什么区别？为什么 DNS 用 UDP？

## 核心答案

- **缓存检查**：先查浏览器 DNS 缓存，再查操作系统缓存（及 `hosts` 文件），命中直接返回；
- **递归查询**：本机向本地 DNS 服务器（运营商或 `8.8.8.8`）发起递归查询，要求它必须给出最终结果；
- **迭代查询**：本地 DNS 缓存未命中时，依次问**根域名服务器**（返回 `.com` 顶级域服务器地址）→ **顶级域服务器**（返回权威服务器地址）→ **权威域名服务器**（返回最终 IP）；
- 本地 DNS 把结果返回客户端，并按 TTL 缓存，后续请求直接复用。

一句话区分：递归是「你替我去问，给我最终答案」；迭代是「我不知道就告诉你该去问谁」。

DNS 基于 UDP 的原因：查询报文小、一次往返即可完成，UDP 无连接开销更小、延迟更低；只有区域传送（主备同步）等大数据量场景才用 TCP。

## 深度解析

- 追问点：为什么分层设计？分散负载、便于各级缓存，根服务器只需维护顶级域的地址表；
- 常见误区：递归查询发生在客户端与本地 DNS 之间，迭代查询发生在本地 DNS 与各级服务器之间，别搞反；
- 延伸：DNS 劫持/污染问题与 `DoH`（DNS over HTTPS）、HTTPDNS 的应对思路——绕过运营商解析，走加密通道拿可信结果；
- CDN 智能调度也依赖 DNS：根据本地 DNS 的地理位置返回就近边缘节点；
- 常见误区：修改解析记录不是立即生效，客户端与各级 DNS 都按 TTL 缓存，迁移时先调小 TTL。
