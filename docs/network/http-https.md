## 问题

HTTP 与 HTTPS 有什么区别？HTTPS 的加密流程是怎样的？

## 核心答案

| 对比项 | HTTP | HTTPS |
| --- | --- | --- |
| 传输方式 | 明文 | TLS 加密 |
| 默认端口 | 80 | 443 |
| 证书 | 不需要 | 需要 CA 证书 |
| 安全性 | 可被窃听、篡改、冒充 | 机密性 + 完整性 + 身份认证 |

HTTPS 建立连接（以 TLS 1.2 RSA 握手为例）：

1. 客户端发送 Client Hello（随机数、支持的加密套件）；
2. 服务端返回 Server Hello + 证书；
3. 客户端验证证书后，生成预主密钥并用服务器公钥加密发送；
4. 双方基于随机数 + 预主密钥算出会话密钥，之后用对称加密通信。

即：**非对称加密交换密钥，对称加密传输数据**。

## 深度解析

- TLS 1.3 只需 1-RTT 完成握手（甚至 0-RTT），删除了 RSA 密钥交换，全面转向 (EC)DHE 前向保密。
- 证书校验链：信任根 CA → 中间 CA → 站点证书，同时校验域名、有效期、吊销状态。
- HTTPS 的开销主要在握手往返与证书验证，会话复用（Session Ticket）与 HTTP/2 可以摊薄成本。
