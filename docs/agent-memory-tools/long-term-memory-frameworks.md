## 问题

跨会话长期记忆除了自己存向量库，有哪些成熟的开源方案？Mem0、Zep 这类框架的思路是什么？

## 核心答案

**共同要解决的四个问题**：存什么（原始对话还是提炼事实）、怎么去重更新、怎么检索、怎么衰减淘汰。

**Mem0 的思路**：

1. 从对话中**自动抽取候选记忆**（LLM 抽取事实条目）；
2. 与现有记忆**比对合并**：判定新增 / 更新（信息变化）/ 无关（丢弃）——解决记忆的版本演进；
3. 对外提供简单的 add / search API，应用按需检索注入。

**Zep（及其图引擎 Graphiti）的思路**：

1. 把记忆组织成**时序知识图谱**：实体、关系，每条带时间有效性；
2. 支持"当前有效"查询与历史回溯——适合"用户的经理是谁（现在）vs 三个月前"这类时序问题。

**工程要点**：所有框架本质都是"抽取 → 合并 → 检索 → 淘汰"的管道封装；轻量场景自建最小版（几条结构化事实 + 向量检索）完全够用。

## 深度解析

- 选型：记忆条目少而稳定 → 自建结构化存储最简单；记忆动态演进、需要去重合并与时序 → 引入 Mem0 类框架；实体关系复杂、有时序查询 → 图谱类（Zep/Graphiti）；
- 标注：这类框架 API 迭代很快，面试讲"它们解决了记忆管理的哪些工程问题"比背 API 更稳；
- 雷区：把原始对话全量存进向量库当长期记忆——噪音大、检索差，记忆的价值在于"提炼"。
