## 问题

讲一下 Tool Calling 的工作机制。模型怎么知道有哪些工具？调用是谁执行的？

## 核心答案

**四步循环**：

1. **注册**：请求时携带工具清单——每个工具的名称、功能描述、参数 JSON Schema（含枚举、必填项）；
2. **决策**：模型判断是否需要调工具；需要则输出**结构化调用意图**（工具名 + 合法 JSON 参数），而不是自然语言描述；
3. **执行**：**应用程序**解析参数、真正执行工具（查数据库、调 API、跑代码）——模型自身不执行任何东西；
4. **回填**：执行结果作为 tool 结果消息追加进上下文，模型基于结果继续生成（可能再次发起调用，形成循环）。

**模型的角色边界**：模型是「决策者」，只负责「选哪个工具、传什么参数」；应用是「执行者」+「安全边界」。

**工程要点**：

- 参数合法性由 Schema 约束解码兜底，但业务校验（如 ID 是否存在）必须应用层做；
- 并行工具调用：现代 API 支持一次返回多个调用，应用并发执行后统一回填；
- 错误也是信息：工具执行失败要把错误消息回填，模型通常会自我修正或换路径。

## 深度解析

- 工具描述质量直接决定调用准确率：name 语义化、description 写「什么时候该用我」、参数说明带示例与取值范围。
- 工具数量多时（几十个以上）模型选择准确率下降，解法是工具检索/分组（先选组再选工具）或渐进式披露。
- 安全边界：参数校验、权限校验、幂等 key、超时与限流都在执行层强制执行——永远不信任模型给的参数。
