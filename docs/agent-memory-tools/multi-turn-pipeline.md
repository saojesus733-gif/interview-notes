## 问题

从用户发消息到收到回复，一个带记忆和工具的 Agent 完整执行链路是怎样的？

## 核心答案

```text
1. 接入层：接收用户消息，鉴权，生成/续接会话 ID
2. 加载状态：从存储读取会话状态（历史摘要、用户画像、任务进度）
3. 上下文构建（Context Builder）：
   a. 取短期记忆（最近 N 轮对话，超限则压缩）
   b. 检索长期记忆（用户偏好、历史结论）
   c. RAG 检索相关知识
   d. 按 Token Budget 组装：System + 记忆 + 资料 + 历史 + 当前输入
4. LLM 决策：直接回答 or 发起工具调用
5. 工具执行循环（ReAct）：
   执行工具 → 结果回填 → 模型继续决策 → ……（护栏：轮数/预算/敏感操作人审）
6. 响应生成：流式输出给用户（SSE）
7. 状态回写：
   a. 本轮对话与工具结果追加到 Chat History（持久化）
   b. 触发记忆抽取（新事实写入长期记忆）
   c. 会话状态更新（Redis + 数据库）
8. 监控埋点：延迟、token 消耗、工具成功率、用户反馈
```

**链路设计的两个核心意识**：

- **上下文构建器是枢纽**：模型看到什么完全由第 3 步决定，效果问题先查这里；
- **写路径与读路径对称**：读的时候（记忆/资料）来自哪里，写的时候（新信息）就要回哪里去。

## 深度解析

- 每一步都要考虑失败：检索失败降级为纯对话、工具失败回传错误让模型自愈、模型超时有兜底话术；
- 流式场景下第 6 步开始输出时，第 7 步的回写要异步进行，但必须保证最终一致（不能因回写失败丢对话）；
- 全链路用统一 trace ID 串联（网关→编排→模型→工具），这是排查多轮问题的基础设施。
