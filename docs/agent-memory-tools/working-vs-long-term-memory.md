## 问题

Agent 的短期记忆和长期记忆分别怎么设计？落地时各有哪些方案？

## 核心答案

**短期记忆（Working Memory）**：当前会话的「工作台」，即模型上下文中的对话状态。

- 内容：系统指令 + 最近对话 + 本次任务的关键中间结论；
- 管理：Token Budget 控制、滑动窗口、超限时摘要压缩；
- 特点：随会话结束而「消失」（归档为历史），生命周期 = 一次会话/任务。

**长期记忆（Long-term Memory）**：会话之外的持久知识，跨会话复用。

- 内容：用户画像与偏好、历史任务结论、领域事实、反馈教训；
- 落地方案：
  1. **向量库**：记忆条目向量化存储，按语义检索注入（最常用）；
  2. **结构化存储**（MySQL/Redis）：存 profile 类字段、键值事实，精确读改；
  3. **文档库**：把长期沉淀组织成可检索的知识文档。
- 关键机制：**写入时机**（实时抽取 vs 会话结束总结）、**检索策略**（按当前任务语义召回 Top-K）、**更新与淘汰**（去重、合并、时效衰减）。

**一句话总结**：短期记忆管理「窗口内的注意力」，长期记忆解决「跨会话不忘事」。

## 深度解析

- 记忆写入要用模型抽取「值得记的事实」（如「用户是 Java 后端」「上次选了方案 B」），而不是存原始对话——存对话是 History，存结论才是 Memory。
- 检索注入长期记忆时注意与 RAG 资料抢预算：优先级 = 任务相关事实 > 偏好类记忆 > 历史闲聊摘要。
- 一致性问题：长期记忆过时会误导决策，重要记忆要带时间戳与来源，并支持显式失效。
