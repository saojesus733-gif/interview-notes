## 问题

为什么说生产级 Agent 系统最终都会演进成状态机（状态图）？这个演进解决了什么问题？

## 核心答案

**起点：自由循环的 ReAct Agent**

```text
while True:
    决策 = llm(上下文)
    if 完成: break
    结果 = 执行(决策)
    上下文.append(结果)
```

简单灵活，但上生产立刻暴露四个问题：**不可恢复**（进程挂了从头再来）、**不可观测**（黑盒循环，出了错不知道卡在哪）、**不可干预**（无法插入人工审批）、**不可测**（没有稳定的结构做回归）。

**演进：显式状态机/状态图**

- 把「状态」显式化为结构化数据（当前节点、计划进度、中间产物、预算计数）；
- 把「控制流」显式化为节点与转移条件（条件边）；
- 每步转移做**检查点持久化**。

**由此免费获得**：

1. **断点恢复**：崩溃后从最近 checkpoint 续跑；
2. **Human-in-the-Loop**：在任意节点挂起等待人工输入再恢复；
3. **可观测**：状态转移日志就是执行轨迹；
4. **可测试**：给定状态 + 节点，可以单独回归；
5. **可优化**：并行化（Fan-out）、超时降级、预算控制都挂在状态与边上。

**一句话**：自由循环把控制流藏在模型脑袋里；状态机把它变成工程资产——这是从 Demo 到生产系统的分水岭。

## 深度解析

- LangGraph、工作流引擎（Temporal 类）、自研编排器殊途同归，都在做同一件事：**显式化状态 + 显式化控制流 + 持久化**；
- 但不要过度工程：一步问答不需要状态机；「演进」的触发点是你开始需要恢复/审计/人审中的任意一项；
- 面试表达：先讲自由循环的四个「不可」，再讲状态机的五个「获得」，最后补一句「按需演进」——体现工程判断力。
