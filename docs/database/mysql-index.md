## 问题

MySQL 的 InnoDB 为什么选择 B+ 树作为索引结构？相比哈希表、B 树、红黑树有什么优势？

## 核心答案

- **对比哈希表**：哈希只支持等值查询，不支持范围查询与排序，而 B+ 树的叶子节点构成有序链表，天然支持范围扫描；
- **对比 B 树**：B+ 树非叶子节点只存键不存数据，单节点能容纳更多键，树更矮（千万级数据通常 3 层），磁盘 IO 次数更少；数据全部在叶子层，查询性能稳定；
- **对比红黑树**：二叉树太高，磁盘场景下 IO 次数不可接受；红黑树适合内存结构。

结合磁盘预读特性：InnoDB 页大小 16KB，B+ 树节点 = 一个页，一次 IO 读取一个完整节点，局部性利用充分。

## 深度解析

- 聚簇索引：叶子节点存整行数据；二级索引叶子存主键值，回表再查聚簇索引，覆盖索引可避免回表。
- 三层 B+ 树可支撑约 2000 万行（假设主键 bigint、行较大时层数会增加）。
- 索引下推（ICP）、最左前缀匹配、页分裂与页合并都是高频追问点。
