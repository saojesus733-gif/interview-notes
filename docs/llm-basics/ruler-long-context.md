## 问题

模型都宣称支持 128K 甚至更长的上下文，但实际做长文档问答效果还是不行。RULER 这类评测揭示了什么？

## 核心答案

1. **RULER（NVIDIA 提出的长上下文基准）**用可控合成任务测"有效上下文长度"：多跳检索、聚合、问答等，且能按需调整难度与长度；
2. **核心发现**：多数模型在各长度区间的表现随长度衰减，**有效上下文长度显著低于标称值**——标称 128K 的模型可能在 32K~64K 区间检索/聚合能力已经明显下滑（具体数值随模型与版本变化）；
3. **根本原因**：标称长度只保证"能处理不报错"（位置编码与显存支持），不保证注意力对全程内容的利用率；训练数据里真正的长文本占比有限；
4. **典型衰减模式**：中间信息利用率低（呼应 Lost in the Middle）、跨段多跳推理失败、全局聚合类任务崩。

## 深度解析

- 工程含义：**长上下文 ≠ 免 RAG**——把最相关内容检索出来放进去，仍比"全塞进去"效果好且便宜；
- 自己业务要做"真实版大海捞针"评估：用真实长文档在多个深度位置埋关键信息，按位置画准确率曲线；
- 雷区：面试中把标称窗口当有效窗口直接给方案（"文档不大，直接全塞 128K 模型"）——要体现"标称 vs 有效"的意识。
