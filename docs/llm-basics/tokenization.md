## 问题

什么是 Token？大模型为什么不能直接按「字」或「词」处理文本？

## 核心答案

- **Token 是模型处理文本的最小单位**：输入文本先经分词器（Tokenizer）切成 token，再映射为 ID 序列送入模型；输出也是 token，最后反解码成文本。
- **为什么不按词**：词表需要覆盖所有词，规模爆炸且无法处理新词（OOV）、形态变化（英语复数/时态）。
- **为什么不按字符**：序列过长，单字符承载的语义太少，上下文窗口浪费严重。
- **折中方案：子词（Subword）分词**，主流算法是 **BPE（Byte-Pair Encoding）**及其变体：从字符开始，迭代合并高频相邻对，高频词收敛成完整 token，低频词拆成多个子词——既控制词表大小（通常几万到十几万），又能表示任意文本。

工程上需要知道的：

1. **中文一般 1 个汉字 ≈ 1~2 个 token**，英文约 1 个单词 ≈ 1~1.5 个 token（随词表与语言而变，需实测）；
2. Token 数直接决定 API 计费、上下文占用、推理延迟；
3. 数字、代码、生僻字符的切分方式常是坑（如大数字被切碎导致算术不稳）。

## 深度解析

- 词表是「训练时冻结」的：换词表 = 换输入分布，基本等于重训模型，所以模型升级 tokenizer 成本很高。
- 字节级 BPE（如 GPT 系列）可以保证任何字节序列都能编码，不会出现 unk。
- 实际项目里估算成本与窗口占用要用官方 tokenizer 计算，不要按字符数粗估。
