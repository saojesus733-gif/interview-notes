## 问题

大模型在知识层面有哪三大缺陷？为什么说 RAG 是针对性的解法？

## 核心答案

| 缺陷 | 含义 | RAG 如何对应 |
| --- | --- | --- |
| **知识截止** | 模型知识冻结在训练数据截止日，不知道之后的事 | 知识库可随时更新，检索最新文档作答 |
| **私有数据缺失** | 企业内部文档、个人数据从未出现在训练集里 | 私有文档入向量库，即插即用 |
| **幻觉** | 不知道的事会编 | 回答前先给依据，「看着资料说」，降低编造空间 |

- 三者的共同根源：**模型知识只来自训练时的参数**，训练完就固定了。
- RAG 的本质是把「知识」从参数里搬出来，放到**外部可更新的知识库**，模型只负责「理解与表达」——知识实时、可管理、可溯源。
- 微调不解决这三个问题：微调改变的是行为模式与能力，往参数里「灌知识」成本高、更新难、还可能加重幻觉。

## 深度解析

- 这三大缺陷是企业落地选择 RAG 优先于微调的主要动因：知识运营（增删改文档）是业务可操作的，重训模型不是。
- 缺陷之间的关联：私有数据问答失败时，模型常用幻觉来「补位」，所以三者会叠加放大。
- 反过来，能力类问题（输出格式、领域话术、任务风格）不在这三大缺陷范围内，才是微调的主战场。
